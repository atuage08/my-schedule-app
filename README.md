# マイスケジュール — 第1段階プロトタイプ

「からだ記録アプリ」と別フォルダーで作成した、外部依存ゼロの静的Webアプリ。実データ・外部API・解析ツールは使用しません。初回に架空の予定とタスクを表示します。

## 検証と配信用ビルド

Node.js 22以上（推奨24）で、プロジェクト内から実行します。ソースの検査・ビルドはWindowsまたはLinuxに対応します。Windowsでは標準のWindows PowerShellと.NETを使用します。追加パッケージのインストールは不要です。

```sh
node scripts/check.mjs
node scripts/test.mjs
node scripts/build.mjs
# 配信対象は dist/ の計20ファイル（公開許可リスト19ファイルと .nojekyll）
```

基本機能先行版の実機検証には、通知開発版から独立したCloudflare Pagesのテストサイトを使用しました。PC内で確認する場合は、`node server.mjs` でビルド済みdistを `http://127.0.0.1:4173/` に表示できます。

CSSとJSの相対参照により、ルート直下でも `/my-schedule-app/` のようなリポジトリ配下でも動く構成です。`.nojekyll` を出力し、実行時依存・CDN・サーバー処理はありません。画面遷移は同一HTML内で完結します。

## 構成

- `src/model.js`: ローカル日付、時刻の初期値、繰り返し、整合性検証、完了処理。UIに依存しません。
- `src/app.js`: 画面構成、入力パネル、保存操作。ブラウザ標準APIだけを使用。
- `src/backup.js` / `src/storage.js` / `src/backup-ui.js`: JSONバックアップ・復元、緊急復旧、Web Locksを使う一括保存、336時間の案内と画面。
- `src/upgrade-notice.js`: 旧版終了案内の確認記録。未確認時は通常画面にも表示します。
- `src/dom.js`: 許可したタグ・属性だけで要素を生成。名称・検索文字列はテキストノードやvalueとして設定し、HTMLとして解釈しません。
- `styles.css`: 色、レイアウト、iPhone safe area、入力パネル。UI評価後に差し替え可能。
- `test/model.test.js`: 日付境界・基本登録条件・完了・繰り越し・保存形式の自動テスト。
- `.github/workflows/`: 自動テストとCodeQLの設定。GitHubへ接続後に実行されます。
- `scripts/build.mjs`: 公開対象を許可リストで限定してdistへコピー。
- `scripts/check.mjs`: ソース構文と秘密情報・連絡先らしい文字列の簡易検査。
- `test/build.test.js`: 公開パス、配信内容、ビルド失敗時の保護、共有対象の除外。
- `scripts/review-zip.ps1`: レビュー用ZIPの作成・全エントリーのハッシュ検証。
- `scripts/secure-source.mjs` / `scripts/windows-source-worker.ps1`: ハンドルを基点とするリンク非追従のソース読み込み・列挙。通常ファイルのみ、1ファイル8MiB以下に限定。
- `test/dom-security.test.js` / `test/files-security.test.js`: HTML文字列、異常パス、ハードリンク、シンボリックリンク／ジャンクション、親ディレクトリ差し替えの回帰テスト。

## 実装仕様

ホームから週／月を同じ場所で切り替えます。下部タブはありません。期限ありは全日付を対象に期限の近い順で最大5件、全件画面は「期限超過／今日／今後7日以内／それ以降」の4グループです。「今後7日以内」は明日〜今日の7日後を含みます。「いつかやる」は検索・ピン留め・編集からの期限設定が可能です。

追加パネルは常に予定が初期選択。今日の開始は現在時刻を10分単位で切り上げ、別日は12:00、終了は1時間後です。開始変更時に所要時間を維持します。「時」は0〜23の数値直接入力、「分」は通常10分刻みの選択です。詳細設定で1分単位へ変更可能。終日は開始日と終了日を含みます。日付の選択UIは端末の言語設定に従います。

繰り返しは毎日／毎週／2週間ごと／毎月／毎年。月末・2月29日は基準日を保持し、存在しない日だけ月末へ調整します。繰り返しタスクは初回期限必須で、起動・画面復帰・保存時に次の期限へ繰り越し、未完了を一つだけ維持します。期限前の完了も次の期限へ進めます。バックグラウンドでの実行・通知はありません。

繰り返し予定・タスクの編集と削除は「今回だけ／すべて」から選択します。「今回だけ」の予定編集は元の回を除外し、元シリーズIDと元の日付を持つ例外予定を作成します。移動・再編集後も関連付けを維持します。予定の「すべて削除」は元シリーズとその例外予定を対象にし、確認画面に例外の件数を表示します。例外予定からの削除は「この例外予定だけ」が初期値で、元シリーズを含む全体削除も明示的に選択できます。タスクの今回だけ編集は元の回を次回へ進め、変更した回を独立したタスクとして保存します。タスクの過去の完了履歴は削除対象にしません。

日付の下には予定の丸と期限付きタスクの四角を表示します。両方ある日は2つ並べ、週／月で共通の判定を使用します。期限なしと完了履歴は印の対象外です。繰り返しタスクは現在の未完了期限だけを表示します。日付の読み上げラベルにも予定・期限付きタスクの有無を含めます。

旧版で既に関連情報なしに作られた独立予定は、名称や日付から推測でシリーズへ結び付けません。既存の無関係な予定の誤削除を避けるためです。関連付けは今回の修正後に行う「今回だけ編集」から保存します。

完了履歴は期限で削除せず保存し、通常は直近90日を表示します。JSONバックアップには全履歴を含みます。ただし件数・容量上限があり、ブラウザのデータ削除・端末紛失を超えて保存を保証するものではありません。古いバックアップへの全置換では、その後の変更と履歴は残りません。同期は未実装です。

削除時には確認画面を表示します。繰り返しの「今回だけ」は対象日と、ほかの回が残ることを表示し、「すべて」は過去・今後のシリーズ全体と明示します。完了履歴は削除しません。

新しく完了したタスクは履歴から未完了へ戻せます。履歴を消さず「完了取り消し済み」として記録します。繰り返しは既存の未完了1件へ統合し、現在の期限・編集を維持します。未完了が削除済みなら、保存した元タスクから範囲内の次回を復元します。ほかの完了済みの回はスキップします。旧形式の履歴は元タスクIDと繰り返し情報がないため、誤復元を防ぐため復元不可の理由を表示し、閲覧は維持します。

日付範囲は2000〜2100年、予定は最大366日間。予定・タスク合計1,000件、履歴10,000件、1シリーズの除外日512件・保存全体4,096件、保存JSONは2,000,000文字までに制限します。上限時は保存を拒否して元データを保護し、自動で履歴を間引きません。完了・復元・削除は検証済みの作業用コピーに適用し、成功時だけ状態へ反映します。長期間の繰り返しは日付の算術計算で探索開始位置を求めます。

## 保存・分離

予定・履歴はlocalStorageの `my-schedule.prototype.v1`、バックアップ案内記録は `my-schedule.backup-meta.v1`、旧版終了の確認は `my-schedule.write-protocol-ack.v1` に保存します。ほかのアプリのキーやlocalStorage.clear()は使用しません。全データ保存は同じWeb Lock内で基準文字列を再比較し、検証後に一括保存・読み戻し確認します。破損時は通常保存を止め、厳格なファイル検証と明示的な最終承認による緊急復旧だけを許可します。確認不能時は成否不確定として同じページの保護停止を維持し、元データを退避する前に再読み込みしないよう案内します。Web Locksがない場合は書き込み停止です。旧版はロックに参加しないため、旧版画面を閉じて開き直す案内を通常画面にも表示します。

CSPで通信先を禁止し、外部画像・フォント・計測・APIは使用しません。画面はDOM APIで生成し、名称・保存データ・DOMから読み戻した値をHTMLとして再解釈しません。保存データは暗号化していません。実データを入れず架空データで試してください。

**公開前の条件:** 同じ `ユーザー名.github.io` 配下のパス違いは同じオリジンです。専用保存キーは衝突を防ぎますが、同一オリジンのスクリプトからの隔離にはなりません。正式運用は専用ドメイン／サブドメイン等でオリジンを分離し、認証・バックアップ方針も別途検討してください。

## 独立レビュー用ZIP

WindowsのPowerShellで実行します。Node.jsと.NET標準機能のみを使います。

```powershell
pwsh -NoProfile -File scripts/review-zip.ps1 -ArchiveName my-schedule-source-review-phase2-security-r4.zip
```

出力は `artifacts/my-schedule-source-review-phase2-security-r4.zip`。既存ZIPは上書きせずエラーにします。別名を指定でき、旧ZIPも保持します。ソース・テスト・設定・Markdown文書・公開用アイコン・SHA-256一覧を含みます。Git管理領域、生成物、公開用アイコン以外の画像、環境ファイル、保存データは除外します。ZIPは保護された読み込みで取得したバイト列から作成し、パスを開き直しません。作成前の簡易スキャンと作成後のハッシュ検証を行います。
