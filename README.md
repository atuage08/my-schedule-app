# マイスケジュール — 第1段階プロトタイプ

「からだ記録アプリ」と別フォルダーで作成した、外部依存ゼロの静的Webアプリ。実データ・外部API・解析ツールは使用しません。初回に架空の予定とタスクを表示します。

## 起動とテスト

Node.js 22以上（推奨24）で、プロジェクト内から実行します。インストール工程は不要です。

```sh
node server.mjs
# http://localhost:4173

node --test
```

iPhoneではPCと同じWi-Fiに接続し、Safariで `http://<PCのLAN内IPv4アドレス>:4173` を開きます。PC側でNode.jsの受信が許可されている必要があります。localhostはiPhone自身を指すため、PCのアドレスを使ってください。サーバーは検証用で、公開用サーバーではありません。

## 構成

- `src/model.js`: ローカル日付、時刻の初期値、繰り返し、整合性検証、完了処理。UIに依存しません。
- `src/app.js`: 画面構成、入力パネル、保存操作。ブラウザ標準APIだけを使用。
- `styles.css`: 色、レイアウト、iPhone safe area、入力パネル。UI評価後に差し替え可能。
- `test/model.test.js`: 日付境界・基本登録条件・完了・繰り越し・保存形式の自動テスト。
- `.github/workflows/`: 自動テストとCodeQLの設定。GitHubへ接続後に実行されます。

## 実装仕様

ホームから週／月を同じ場所で切り替えます。下部タブはありません。期限ありは全日付を対象に期限の近い順で最大5件、全件画面では期限超過／今日／明日／日付別にグループ化します。「いつかやる」は検索・ピン留め・編集からの期限設定が可能です。

追加パネルは常に予定が初期選択。今日の開始は現在時刻を10分単位で切り上げ、別日は12:00、終了は1時間後です。開始変更時に所要時間を維持します。詳細設定で1分単位へ変更可能。終日は開始日と終了日を含みます。時刻は独立した時・分の選択欄で24時間表記を維持します。日付の選択UIは端末の言語設定に従います。

繰り返しは毎日／毎週／毎月。月末は基準日を保持し、該当しない月は月末にします。繰り返しタスクは初回期限必須で、起動・画面復帰・保存時に次の期限へ繰り越し、未完了を一つだけ維持します。期限前の完了も次の期限へ進めます。バックグラウンドでの実行・通知はありません。

繰り返し予定・タスクの編集と削除は「今回だけ／すべて」から選択します。「今回だけ」の予定編集は元の回を除外し、独立した予定を作成します。タスクも元の回を次回へ進め、変更した回を独立したタスクとして保存します。「すべて」はシリーズ全体（過去の予定も含む）へ適用し、完了履歴は変更しません。

完了履歴は期限で削除せず保存し、通常は直近90日を表示します。ただしブラウザのデータ削除・容量制限・端末紛失を超えて保存を保証するものではありません。同期・バックアップ・復元は後続対応です。

## 保存・分離

保存先はlocalStorageの `my-schedule.prototype.v1` のみ。ほかのキーを読み書きせず、`localStorage.clear()` も使用しません。読み込み時と保存前に形式と日時の整合性を検証します。読み込み失敗時は元データを上書きせず保存を停止し、書き込み失敗時はメモリー上の変更を戻します。保存失敗は画面に表示します。別タブからの変更はstorageイベントで再読込しますが、複数タブ間の完全なトランザクション制御はありません。

CSPで通信先を禁止し、外部画像・フォント・計測・APIは使用しません。名称はHTMLエスケープします。保存データは暗号化していません。実データを入れず架空データで試してください。

**公開前の条件:** 同じ `ユーザー名.github.io` 配下のパス違いは同じオリジンです。専用保存キーは衝突を防ぎますが、同一オリジンのスクリプトからの隔離にはなりません。正式運用は専用ドメイン／サブドメイン等でオリジンを分離し、認証・バックアップ方針も別途検討してください。

## GitHubと公開

専用の新規リポジトリへ接続し、`prototype/phase-1` から `main` へのPRを作成します。既存アプリのリポジトリやPages設定には接続しません。PRの `Prototype checks` と `CodeQL` を確認し、iPhone実機評価後にマージ・公開してください。リポジトリの保護設定でこれらを必須検査にする必要があります。

CodeQL設定は [GitHub公式資料](https://docs.github.com/en/code-security/reference/code-scanning/workflow-configuration-options) に基づきます。リポジトリの可視性・契約によってCodeQLの利用条件が変わるため、接続後に実行結果を確認してください。現在は公開ワークフローを自動実行しません。
