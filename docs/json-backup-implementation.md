## 実装した保存仕様

予定・タスク・全履歴は既存の `my-schedule.prototype.v1`、案内用の記録は `my-schedule.backup-meta.v1` です。前者の形式はversion 1のままです。既存の旧形式履歴、例外予定の関連付け、復元用の元タスク情報を維持します。現在のitemsに元タスクがないことだけで履歴を拒否しません。

全データ書き込みは `my-schedule.data-write.v1` の同じWeb Lockを使用します。ロック取得後、保存先の生文字列と操作基準、同一画面の更新番号を比較します。不一致なら中止します。確認・共有・ファイル選択中にロックを保持しません。遅延したstorageイベントではevent.newValueを採用せず、最新保存値を読み直します。キー削除・clearは保存停止となり、起動後にサンプルを再生成しません。起動時も、既存のメタ記録があるのにデータキーだけがない場合は初期化しません。すべてのサイトデータが消えた状態と完全な新規利用は識別できません。

保存前に作業コピーを検証し、1回のsetItemで置き換えます。保存不能では元データを保持します。書き込みを試みた後は生文字列一致とデータ検証で読み戻しを確認します。確認不能は成否不確定として「保存失敗」と区別し、同じページでは保護停止を維持します。第三者の更新へ旧データを勝手に書き戻しません。

メタ記録の保存失敗は、予定・履歴の保存結果と分離して表示します。メイン画面にも警告を保持し、通常の保存完了通知だけで警告が消えないようにしています。

## JSON・復元

形式はformat=my-schedule-backup、formatVersion=1、exportedAt=UTC日時、data={version,items,history}です。UTF-8、8,388,608バイト以下。先頭BOMは1つだけ許容し、不正UTF-8はfatal復号で拒否します。JSON解析前のコンテナー深さは8以下。解析後は反復走査で値500,000以下、配列長10,000以下、各オブジェクト32キー以下。許可キー・版・日時・関連情報を検査し、内部serializeState(data)も2,000,000文字以下に制限します。出力したバイト列も同じ入力検証を通します。

バックアップは保存済みの正常データを読み取り、その後変わらないFileとdataへ固定します。90日以前の履歴もすべて含みます。自動繰り越しの保存に失敗した場合は、その変更を含まない保存済みデータを書き出します。未保存フォームを含めません。

元バックアップとrollTasks適用後の候補を分離し、件数・期限変更・次回がなく除かれるタスクの名称と理由を表示します。日付の変化で候補が変われば、保存せず候補を更新して承認をやり直します。古いバックアップへの全置換で、以後の変更・履歴が失われることを明示します。マージは行いません。

## 緊急復旧・退避

破損・検証エラー中もファイル選択と検証を利用できます。正常なバックアップに対して通常と同じ検証を行い、明示的な全置換承認、元データ消失の理解、退避保存確認または退避なし続行の追加確認を求めます。

退避ファイルはUTF-16LEのコード単位をそのまま格納したapplication/octet-streamの.binです。最大8MiB、切り詰めません。不正サロゲートも保持し、通常のバックアップとしては受理しません。保存不能・キャンセル時に退避済みとしません。書き込み後の確認に失敗した場合にも、元の破損文字列をメモリーに保持し退避できます。タブを閉じるとこのメモリーは失われるため、復旧前のファイル退避を案内します。

localStorage自体が読めない場合、ファイル検証は可能ですが、保存先の再比較ができるまで置き換えは停止します。

## iPhone・案内

準備済みの同じFileを、ボタン操作から共有します。canShare後の失敗・キャンセルにも対応し、ダウンロードの別ボタンは共有の対応有無にかかわらず用意します。共有成功・ダウンロード開始では確認日時を更新しません。「このJSONファイルを保存できました」の明示的な操作だけで、そのファイルのdataダイジェストと日時を記録します。共有中の変更を確認対象に混ぜません。

保存確認から336時間以上経過し、確認したdataと現在の正式なdataが異なる場合だけ促進表示します。exportedAtと画面状態は比較しません。自動繰り越しの保存による変化を含みます。OS通知はありません。初期サンプルだけでは促進せず、実際の利用者変更の保存成功後に案内します。内容が変わらない保存、サンプルの自動保存、自動繰り越しだけでは初回変更記録を立てません。表示を閉じるとその利用中は再表示せず、再起動で再評価します。

記録なし・破損は確認不能としてバックアップ画面に表示します。別タブの確認記録は再読込します。時計後退や未来の確認日時は経過時間を確定せず案内します。アプリを閉じている間の時計変更を完全に検知する保証はありません。復元・復旧はバックアップ保存確認ではありません。

iOS 17以降を検証対象としますが、実機未確認です。Web Locksがない環境では通常保存・復元・記録更新を停止し、正常データの閲覧・書き出しのみとします。旧版画面はロック非参加なので、旧タブ・ホーム画面版を閉じ、新版を開き直す案内を表示します。

## 独立レビューで重点確認する点

1. storage.jsの全書き込み経路が同じロックを使い、ロック取得後の基準照合を省略していないか。app.jsの成功通知・パネル終了がawait後か。
2. 書き込み失敗と読み戻し不能が区別され、第三者の変更を巻き戻さないか。
3. 通常／緊急復旧の承認、退避対象の基準一致、破損時にも入口が使えること。
4. backup.jsの上限・BOM・fatal UTF-8、旧履歴互換性、出力の再検証、候補変更時の再確認。
5. 確認記録が準備済みFileのdataに結び付き、共有・ダウンロード・復旧が自動的な保存確認になっていないか。
6. UIがHTMLとして文字列を解釈せず、本文・破損文字列をログへ出さず、退避ファイルを正常バックアップと混同しないか。
