# 基本機能先行公開候補

`codex/basic-release-candidate` はmainの `89e10fa` を基点とする独立worktreeで準備した基本機能先行版です。通知データの互換処理を含みます。通知開発は別ブランチで継続します。

## 通知停止と既存データの扱い

共通制御はsrc/features.jsのNOTIFICATIONS_ENABLED=false。URL・localStorage・呼び出し側の引数から有効化できない。V3_READY=false、REMOVAL_READY=falseも維持する。旧テスト送信、v3変更、解除、照合、変更後確認、結果解析・保存を入口でも停止する。通知画面は生成せず、hashchange/pageshowの結果処理を登録しない。

過去の結果フラグメントで起動・復帰した場合は、保存領域の読み取りだけを行い、サンプル初期化・自動繰り越しをしない。結果を解析・受理・保存・再送しない。通常起動時の初期化と基本タスクの繰り越しは維持する。

通常保存は通知用オプションを渡されても無視する。モデル内の通知依頼生成も停止する。通知なしの予定・タスクの基本操作は、通知解除待ちや移行原本領域を読み書きしない。通知情報付きの既存項目（notificationフィールド、v3 record、移行済み旧解除待ちに関連する項目）は保護対象とし、編集・削除・変更によるID再利用を保存前にも拒否する。閲覧・全データのJSON書き出しは可能。

v1/v2/v3のデータ検証は残す。通常操作で通知フィールドや連携情報を削除・新規作成・改変せず、保存形式を自動昇降格しない。明示的なJSON全置換は別の操作として従来の厳格検証・確認を維持する。異なる保存形式のバックアップを明示復元する際の原本保護、およびv3復元時のmode=review/pending=suspendedは従来の安全処理として残す。Apple側を変更せず、実状態との一致を仮定しない。

既存の移行原本の閲覧・書き出しは残す。破損した原本領域はそのパネルで説明し、通常の基本操作を停止する理由にしない。保護対象を編集可能にする互換処理やApple側の休止は、通知開発へ分離する。保護を解除するための項目コピー・自動再ID発行は行わない。

## テスト方法

Node.js 24で `node scripts/test.mjs` を実行する。基本機能・保存・バックアップ・セキュリティと先行版テストは通知無効の通常モジュールで実行する。既存の通知・移行・旧通知画面テストは、別Nodeプロセスのtest/fixtures/notification-development.jsで、メモリー内の共通フラグだけをtrueとして回帰を維持する。ソースや公開ファイルを変更しない。V3_READYとREMOVAL_READYはその環境でもfalseのまま。

testローダー・browser検証fixture・scriptsは公開許可リストに含めない。`node --test test/*.test.js`で両環境を混ぜず、上記ランナーを使う。GitHub Actionsの呼び出しもランナーへ更新したが、リモート実行はしていない。

追加したtest/basic-release.test.jsは15件。全送信入口、UI生成停止、結果URL、通知領域異常、基本CRUD・完了取り消し、通知付き項目の保持、v1〜v3往復と復元、緊急復旧、保存失敗・競合・読み戻し不能、公開許可リストを検証する。

隔離ブラウザー検証には `scripts/browser-basic-test.mjs` と `scripts/browser-backup-test.mjs` を使います。一時プロファイル、127.0.0.1、架空データで実行します。通知開発専用のブラウザー検証ではメモリー上の配信ポリシーを切り替えます。基本版のブラウザー検証は通知無効で実行します。

## 公開前の条件

Windows Chrome、iPhone Safari、iPhoneホーム画面追加版で、主要機能、データ保持、JSONバックアップ・復元を実機確認済みです。最終修正後には、繰り返し種別の変更、完了後の次回期限、データ保持も同じ3環境で確認しました。正式公開前には、最終コミットの検査と、実機確認に使った配信物との照合が必要です。

正式版と通知開発版、からだ記録アプリは異なるオリジンで運用します。設定確認時点でGitHub Pagesは無効（Branch: None）で、Cloudflare Pagesの `my-schedule-basic-test` はGitリポジトリ未接続でした。正式公開先の設定、実際の応答ヘッダーとキャッシュ、候補のGitHub Actions・CodeQL結果は公開前に確認します。Windowsで未検証のリンク防御6件は、リンク作成可能な環境で `MY_SCHEDULE_REQUIRE_LINKS=1` を指定して検証します。

Service Worker、外部API、依存パッケージ、権限は追加しない。端末内データ・平文JSONバックアップは引き続きブラウザ保存領域削除や端末紛失への保証を持たない。書き込み後に成否を確認できなければ保護停止を維持し、元データを勝手に戻さない。
